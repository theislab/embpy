# Build spec: `docs/notebooks/small_molecules.ipynb` deep dive

Target: 100–125 cells, matching the depth of `genes.ipynb` (128) and
`proteins.ipynb` (89). Generated by `scripts/notebook_generators/small_molecules_part1..6.py`,
assembled by `assemble.py`, executed once with nbconvert.

## Non-negotiable house pattern

Copy these conventions exactly from `scripts/notebook_generators/genes_part*.py`.

### Generator file skeleton

Part 1 uses the long-docstring form; parts 2–6 use the one-line form.

```python
"""Part N of docs/notebooks/small_molecules.ipynb -- <what this part covers>."""
from __future__ import annotations
import json, sys
from pathlib import Path

CELLS: list[tuple[str, str]] = []
def md(s: str) -> None: CELLS.append(("markdown", s.strip("\n")))
def code(s: str) -> None: CELLS.append(("code", s.strip("\n")))

# ============================================================ A. <section>
md(r"""
## <heading>
...
""")

code(r"""
...
""")

Path(sys.argv[1] if len(sys.argv) > 1 else "cells_partN.json").write_text(json.dumps(CELLS))
print(f"part N: {len(CELLS)} cells")
```

Part 1 names the helper argument `src`; parts 2–6 name it `s`. Both builders
always take a raw triple-quoted string opening with a newline. `r"""` is used
unconditionally, markdown included. Nothing is imported from embpy at
generation time.

### Style rules

- One `#` H1 (`# Small molecules`), first cell. Sections `##`, subsections
  `###`. Never `####`.
- Only the three comparison sections are numbered: `## 1. Global geometry`,
  `## 2. Local neighbourhoods`, `## 3. Visual comparison`.
- Cross-references use GitHub anchor slugs: `[Compare](#1-global-geometry)`.
  Sibling notebooks by bare filename: `[genes](genes.ipynb)`.
- ASCII ` -- ` for dashes. **No em dashes.** (genes uses zero.)
- British spellings: normalised, colouring, neighbourhoods, summarise,
  tokeniser, specialisation.
- Prose: second person, present tense, declarative. Paragraphs 2–6 lines,
  hard-wrapped at ~80 columns.
- The voice is adversarial toward its own claims. Use these moves:
  - state a prediction, then "That is a prediction, and the
    [section](#...) scores it rather than assuming it."
  - "measure it rather than asserting it"
  - name the failure mode before the result
  - "Two practical points:", "Three caveats, all of which bound how far this
    can be pushed:"
  - bold lead-ins on list items: `* **Resolve once, embed many.**`
- `**bold**` for the claim, `*italic*` for a word used precisely, backticks for
  every API name, kwarg, `.obsm` key, path and source location
  (`src/embpy/models/molecule_models.py:419`).
- Blockquote callouts for cross-cutting warnings, always with a bold lead:
  `> **Structural, not causal.** ...`
- Markdown tables carry the design rationale. Recurring shapes:
  `| Section | Question |`, `| Key | Model | Why it earns a slot |`,
  `| Target | What it is | Prior expectation |`.
- Code cells wrapped at <= ~88 chars. No `%` magics, no `!pip`.
- `CONSTANTS_IN_CAPS` declared inside the cell that first uses them.
- Comments are full-sentence prose explaining a *decision*, not restatements.
- Every DataFrame shown with `display(df.round(3))`.

## The panel (part 1 defines it; every later part relies on it)

Five families of eight. Chosen so structural similarity and mechanism
similarity *disagree*: two families are tight structural series that any
fingerprint will recover, two are mechanistically coherent but structurally
diverse, and the kinase inhibitors share a target class while spanning
scaffolds.

```python
PANEL = {
    "statin": ["atorvastatin", "simvastatin", "lovastatin", "pravastatin",
               "rosuvastatin", "fluvastatin", "pitavastatin", "mevastatin"],
    "benzodiazepine": ["diazepam", "lorazepam", "alprazolam", "clonazepam",
                       "midazolam", "temazepam", "oxazepam", "chlordiazepoxide"],
    "kinase_inhibitor": ["imatinib", "dasatinib", "nilotinib", "erlotinib",
                         "gefitinib", "sorafenib", "sunitinib", "lapatinib"],
    "nsaid": ["aspirin", "ibuprofen", "naproxen", "diclofenac", "celecoxib",
              "rofecoxib", "indomethacin", "meloxicam"],
    "beta_blocker": ["propranolol", "atenolol", "metoprolol", "bisoprolol",
                     "carvedilol", "nadolol", "timolol", "labetalol"],
}
```

Design notes to state in prose:
- statins and benzodiazepines are tight congeneric series -- a Morgan
  fingerprint should recover them almost perfectly. If a model *cannot*, that
  is a red flag about the model, not about the panel.
- kinase inhibitors span scaffolds (imatinib's phenylaminopyrimidine vs
  sorafenib's diaryl urea) but share a protein family. Fingerprints should do
  *worse* here. A learned representation might do better. That is the
  prediction the purity section scores.
- NSAIDs share a mechanism (COX inhibition) across salicylate, propionic acid,
  coxib and oxicam scaffolds -- the hardest family for a structural method.
- rofecoxib is in the panel deliberately: it is withdrawn, and the annotation
  section uses it to show the safety record surfacing.
- imatinib is in the panel deliberately: it is the compound whose mechanism of
  action embpy used to report as empty.

## Model roster

Runnable on the pixi `default` env (torch 2.10, transformers 4.48.1):

| key | dim | notes |
| --- | --- | --- |
| `maccs_fp` | 167 | only key whose dim is not 2048; 166 public keys, bit 0 unused |
| `morgan_fp` | 2048 | ECFP4 binary, radius fixed at 2 by the registry |
| `morgan_count_fp` | 2048 | same bits, counts instead of presence |
| `rdkit_fp` | 2048 | topological / Daylight-like |
| `atom_pair_fp` | 2048 | |
| `torsion_fp` | 2048 | registry key `torsion_fp`, internal type `topological_torsion` |
| `chemberta2MTR` | 384 | 3 blocks, 12 heads, character-level tokeniser. `max_position_embeddings=515`, wrapper clamps to 512 |
| `chemberta2MLM` | **768** | 12 blocks, BPE tokeniser. Not 384 -- the two ChemBERTa checkpoints differ in width as well as objective |


**`molformer_base` cannot load in this environment** (verified). Its
`trust_remote_code` module imports `transformers.masking_utils`, which does not
exist in transformers 4.48.1 -- the version the env pins for ESM compatibility.
The root cause is `ModuleNotFoundError: No module named
'transformers.masking_utils'`, wrapped by `MolformerWrapper.load` into
`RuntimeError: Could not load MolFormer ...` at
`src/embpy/models/molecule_models.py:287`, then into `ModelLoadError` by
`_get_model`. Attempt it in the sweep, catch it, and report it -- the same
honest-failure slot genes uses for "Why Enformer is not in the sweep". Do not
put it in `ROSTER` as if it worked.

Verified attention facts (`extract_attention` takes **tokenised `input_ids`**,
not a SMILES string):
- `chemberta2MTR`: 3 blocks, 12 heads, character-level tokeniser. Aspirin
  tokenises to 23 tokens; attention is `(1, 12, 23, 23)` per block.
- `chemberta2MLM`: 12 blocks, 12 heads, BPE tokeniser. The same aspirin is 15
  tokens; attention is `(1, 12, 15, 15)`. The two ChemBERTa checkpoints differ
  in depth, width *and* tokenisation, which is the tokeniser-contrast section.

Deliberately excluded, and say so in a "Skipped on purpose:" paragraph:
- `minimol` -- needs `embpy[minimol]`; torch-sparse/torch-scatter only build
  with torch pre-installed.
- `mhg_gnn` -- needs a git package, and has no pyproject extra, so a missing
  backend reports `DependencyError(package="unknown")`.
- `mole` -- **unreachable through `BioEmbedder`**: `_get_model` constructs
  `MolEWrapper(model_path_or_name="mole")` with no `checkpoint_path`, so
  `load()` raises at `src/embpy/models/molecule_models.py:944`. It is listed
  by `list_available_models("molecule")` but cannot be run. This is worth a
  short honest subsection -- the same "keep the catalogue honest" move
  `genes_part5.py` makes for `has_attention`.
- `atom_pair_count_fp`, `torsion_count_fp` -- the binary/count contrast is
  already made once with Morgan; two more pairs add cost, not insight.

Capability-map cell: loop over `ROSTER + ["minimol", "mhg_gnn", "mole"]` with
`embedder.get_model(key, load=False)`, columns exactly
`model, wrapper, has_attention, status`, sentinel `"-"` / `None`, status
`"available"` or bare `type(exc).__name__`, `.set_index("model")`.

## Section assignment

### part 1 -- intro, panel, catalogue (target 14 cells)
1. `# Small molecules` -- H1, "What you'll learn", four-question roadmap table
   linking to anchors, Prerequisites paragraph.
2. imports preamble cell.
3. `## A panel where structure and mechanism disagree` -- PANEL, the design
   table `| Family | What it is | Prior expectation |`, build `mol_space`.
4. `## Which molecule models does embpy have?` -- `model_catalog`, roster table,
   "Skipped on purpose:", capability-map cell. Note honestly that unlike the
   gene catalogue, `model_catalog("molecule")["family"]` is the constant string
   `"molecule"` for all 14 rows, so it cannot be the taxonomy here -- the
   install tier is. Cross-check it against
   `tl.list_embedding_models("small_molecule")` for set equality.

### part 2 -- resolution and the sweep (target 22 cells)
5. `## Resolve the compounds, and measure them before trusting anything`
   - `DrugResolver.name_to_smiles_resolved` over the 40 names; record
     `.source` so the answering API is visible.
   - RDKit canonicalisation; assert 40/40 resolved, and *show* the count
     rather than asserting it silently.
   - measure MW, heavy atoms, ring count; a table per family.
   - **The tokenizer audit.** `ChembertaWrapper.embed_batch` *skips* SMILES
     longer than `max_len` and returns `None` in that slot, which
     `_aligned_matrix` then drops -- so a too-long compound vanishes from the
     matrix without an error. Measure token lengths against the 512 clamp
     before embedding, and say what would happen if one exceeded it. This is
     the molecule analogue of the ESM window audit in `proteins_part1.py`.
6. `## Embed every molecule model` -- the sweep, one `embed` per key, timings,
   `clear_model_cache()` between the transformer models.
   - `### The fingerprints: eight bit vectors, six algorithms`
   - `### The learned representations`
   - `### Binary or count: the same bits, weighted differently`
7. `## One molecule space, two views` -- `mol_space` (may carry NaN rows) vs
   `dense_space` (intersection). Same contract genes states.

### part 3 -- geometry (target 20 cells)
8. `## 1. Global geometry` -- `tl.alignment_matrix` with tsi/qsi/linear_cka/
   mutual_knn, the 4-metric matrix, `tl.similarity_correlation`, and the
   dimensionality caveat (167 vs 2048 vs 384 vs 768 -- state that TSI is
   dimension-agnostic and why that matters here).
9. `## 2. Local neighbourhoods` -- `tl.knn_jaccard`, `pl.knn_overlap`.
   - `### Two compounds, every space` -- the concrete probe. Use
     **nilotinib** (a deliberate imatinib analogue: same phenylaminopyrimidine
     core, so fingerprints should call them near-identical) and **celecoxib**
     (same COX-2 mechanism as rofecoxib, entirely different scaffold, so
     fingerprints should miss it). Report both neighbour lists per space.
10. `## 3. Visual comparison` -- `pl.all_embeddings`, `pl.plot_embedding_space`.

### part 4 -- does the geometry track biology? (target 20 cells)
11. `## Does the geometry track biology?` -- `pl.knn_label_purity` /

### part 5 -- annotation, the ChEMBL depth (target 26 cells)

This is the part the whole notebook exists to justify, and it is new surface.

15. `## Annotate the molecules` -- `tl.annotate_molecules` for the structural
    and physicochemical layer (`mol_*` columns).
16. `## The clinical record` -- `tl.annotate_drug_perturbations`. Show the
    `drug_*` columns as a table across the panel. Then, in subsections:
    - `### Development status` -- phase, first approval, routes, availability.
      Note `max_phase` `None` means preclinical, and `-1` means ChEMBL cannot
      assign a phase; those are different claims.
    - `### What each drug is for` -- indications as MeSH/EFO with the phase
      reached *per indication*; the merge that collapses repeated rows.
    - `### The safety record` -- rofecoxib surfacing as `Withdrawn` /
      `cardiotoxicity` / 2004, and the black box column across the panel.
    - `### Where the WHO puts them` -- ATC levels; cross-tabulate
      `drug_atc_level1` against the hand-built `family`. They will not agree
      perfectly, and the disagreements are the interesting part.
    - `### Mechanism, and the parent-molecule trap` -- a `> **...**`
      callout plus a short table. ChEMBL registers drug-level rows against the
      **parent** molecule, so filtering `mechanism` on `molecule_chembl_id`
      returns zero rows for any drug curated against a salt.
      `mechanism?molecule_chembl_id=CHEMBL941` (imatinib) returns nothing while
      `parent_molecule_chembl_id=CHEMBL941` returns four. Show the count both
      ways with `ChEMBLAnnotator` and a raw `requests` call so the reader sees
      the trap, not just the fix. Same rhetorical slot as genes' "A
      calling-convention trap" and "The same class of trap, already sprung
      inside embpy".
    - `### Targets, as genes rather than accessions` -- `get_target_profile`:
      gene symbol, UniProt accession, protein family, best/median pChEMBL.
      Include the second trap: a ChEMBL "target" can be a **cell line**
      (K562 outranks every protein target for imatinib on raw potency), so
      `target_type` has to be filtered before the most potent row means
      "primary target". `summarize_selectivity` does that filtering.
    - `### Selectivity` -- the pChEMBL window between the best and second-best
      protein target, across the panel.
    - `### How they are cleared` -- `get_metabolism`; aspirin to salicylic acid
      via esterases; note prodrugs.
17. `## Does the embedding know the clinical record?` -- re-run purity against
    `drug_atc_level1` and `drug_target_class` instead of the hand-built
    `family`. Colour the UMAP by `drug_development_phase`. State plainly
    whether a structural fingerprint recovers a *therapeutic* label, and note
    the confound (congeneric series share both structure and ATC class).

### part 6 -- downstream, molecule-only, close (target 22 cells)
18. `## Downstream: which model predicts a measured property?` --
    `tl.benchmark_embeddings`. Predict a continuous readout that is *not*
    trivially recoverable from the fingerprint: use `drug_best_pchembl` or

19. `## Molecule-only: a fingerprint bit is not a feature` -- take the

20. `## Molecule-only: scaffold hopping` -- do any of the spaces put
    celecoxib near rofecoxib (same target, different scaffold)? Report per

21. `## Molecule-only: ChEMBL analogs vs embedding neighbours` --

22. `## Molecule-only: the same drug, two SMILES` -- salt vs parent form via

24. `## What we found` -- verdict re-print, 6 numbered practical points,

## Correctness constraints

- `embedder.embed(...)` for molecules: `entity_type="molecule"`,
  `id_type="smiles"`, `obs_column="smiles"`, `output="anndata"`,
  `attach_to="obs"`, `key="X_<model>"`. Matrix lands in `.obsm[key]`.
- Row ids are canonicalised SMILES, so resolve to SMILES **once** in part 2
  and reuse.
- `RDKitWrapper` pooling is `["flat"]` and the value is ignored -- do not pass
  a pooling kwarg expecting it to matter.
- `maccs_fp` is 167-wide and ignores any `n_bits` argument.
- `extract_attention` **does** work on `chemberta2MTR` (verified: `layers=None`
  yields blocks `{0,1,2}`, each `(1, 12, n_tokens, n_tokens)`). It emits a
  `RobertaSdpaSelfAttention ... falling back to the manual attention
  implementation` warning on every call, which the preamble must quiet.
  `RDKitWrapper.has_attention` is `False` (`molecule_models.py:442`).
- `tl.block_to_hidden_state_index(b) == b + 1` (index 0 is the embedding layer);
  `tl.block_to_attention_index(b) == b`.
- Everything must run on the pixi `default` env. No GPU, no cluster.
- Live APIs (PubChem, ChEMBL) are load-bearing. Wrap each network stage so one
  failure degrades to a reported gap rather than a traceback that stops the
  notebook -- but do **not** hide the failure; print what was missed.
